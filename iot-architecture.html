Vagrant, K3s & K3d

How the three tools of Inception of Things fit together. The subject requires the whole project to live inside one main Linux VM. Inside it, K3s is the Kubernetes in every part of the project. Vagrant and K3d are two different ways to give it machines to run on: nested virtual machines for P1 and P2, Docker containers for P3 and the bonus.

Main VM (required by the subject) Vagrant / nested VMs Docker / K3d K3s (Kubernetes) Your workloads
Everything runs in the main VM. The host can be any machine (Linux, Windows, macOS) running any hypervisor. Vagrant, the second hypervisor, Docker, K3d and kubectl are all installed inside the main VM. P1 and P2 therefore need nested virtualization enabled on that main VM. P3 does not, because it only uses containers.
K3s is in both setups. Both setups run the same K3s binary in server mode (control plane) or agent mode (worker). The only difference is where it runs: inside a nested VM created by Vagrant, or inside a Docker container created by K3d.
