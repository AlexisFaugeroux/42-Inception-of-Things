KVM, QEMU, libvirt & virt-manager

VirtualBox is a single product that does everything, from the window you click in down to the kernel driver. On Linux, the same job is split between several separate open-source projects, each doing one layer. KVM runs the VM on the CPU, QEMU emulates the hardware, libvirt manages VMs, and virt-manager, virsh or Vagrant are the tools you use.

What each one is

KVM

Kernel-based Virtual Machine. A module of the Linux kernel that uses VT-x/AMD-V to run guest code directly on the CPU. It exposes /dev/kvm, but it emulates no hardware and has no interface: on its own, it can't start a VM.

QEMU

A program that emulates a whole machine: disks, network cards, display, USB. Alone, it emulates the CPU too (slow). With -accel kvm, it lets KVM run the CPU and only handles devices (fast). Each VM is one qemu-system-* process.

libvirt

A management layer and API above QEMU (and other hypervisors). It stores each VM as an XML “domain”, manages virtual networks and disk pools, and starts and stops the QEMU processes. Every tool below talks to libvirt, never to QEMU directly.

virt-manager

A desktop GUI for libvirt: the closest thing to the VirtualBox window. Create VMs, open their console, change CPU and RAM, take snapshots. It can also manage a remote machine over SSH.

virsh

libvirt's command-line tool, the equivalent of VBoxManage. virsh list --all, virsh start, virsh shutdown, virsh dumpxml…

vagrant-libvirt

A Vagrant plugin that adds the libvirt provider. Your Vagrantfile stays almost the same, but the provider block and a few options change.
